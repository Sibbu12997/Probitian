## 📋 Overview

The Email Campaign Broadcast Engine allows administrators to create, test, schedule, and send rich HTML newsletter campaigns to active ProBitian subscribers directly from the Admin Control Center.

---

## 🏗 Architecture & Delivery Pipeline

```
ADMIN PORTAL (#/admin)
        ↓
Create Campaign (Name, Subject, Preview Text, Content, Audience)
        ↓
Save Draft → Supabase `email_campaigns` Table
        ↓
Confirm Send Broadcast
        ↓
Load Active Subscribers from Supabase `newsletter` Table
        ↓
Create Recipient Records in `email_campaign_recipients`
        ↓
Update Campaign Status = 'sending'
        ↓
Dispatch Batch Emails via Server-Side Express → Gmail SMTP
        ↓
Track Individual Recipient Results (Success / Failure)
        ↓
Update Campaign Status → 'sent' | 'partially_sent' | 'failed'
```

## ✉️ Email Delivery Provider

- **Active Provider**: **Gmail SMTP** via Nodemailer (`GMAIL_USER` and `GMAIL_APP_PASSWORD`).
- **Sender Address**: `probitianofficial@gmail.com`
- **Inactive / Historical Providers**: Resend API is not the active delivery engine. All email traffic passes securely through Gmail SMTP.

## 🔄 Campaign Status Lifecycle

1. **Draft (`draft`)**:
   - Initial state when a campaign is created and saved.
   - Content and parameters can be edited freely.
   - Saved in Supabase `email_campaigns`.
2. **Scheduled (`scheduled`)**:
   - Campaign configured for future broadcast at `scheduled_at`.
3. **Sending (`sending`)**:
   - Active broadcast state.
   - Server fetches active subscribers and iterates through the recipient queue.
4. **Sent (`sent`)**:
   - All recipients processed with 100% successful delivery.
5. **Partially Sent (`partially_sent`)**:
   - Broadcast completed, but one or more individual recipient dispatches failed due to invalid emails or SMTP throttling.
6. **Failed (`failed`)**:
   - Broadcast aborted due to a critical system error (e.g., SMTP authentication failure or network outage).

## 📊 Recipient Tracking (`email_campaign_recipients`)

Every campaign broadcast logs individual recipient delivery records in `email_campaign_recipients`:
- `id`: Unique UUID
- `campaign_id`: Foreign key to `email_campaigns(id)`
- `subscriber_id`: Foreign key to `newsletter(id)`
- `email`: Recipient email address
- `status`: `pending` | `sent` | `failed`
- `provider_message_id`: SMTP message ID returned by Gmail
- `error_message`: Logged error message if delivery failed
- `sent_at`: Timestamp of delivery attempt

## 🧪 Test Email Capability

Administrators can dispatch a single test email prior to launching a full campaign:
1. Click **Send Test Email** inside the campaign editor modal.
2. Enter a verified target test email address.
3. Express server dispatches the compiled campaign HTML via Gmail SMTP.
4. Verify layout, images, CTA buttons, and formatting in your inbox.

## 📬 Unsubscribe Handling

Every campaign email generated by ProBitian includes a compliant footer containing:
- Official sender information (`probitianofficial@gmail.com`).
- Direct **Unsubscribe link**: `https://probitian.ai.studio/#/unsubscribe?email={recipient_email}`.
- Clicking unsubscribe updates the subscriber's status in Supabase `newsletter` to `unsubscribed` (`unsubscribed_at = NOW()`), preventing future campaign dispatches.

---

## ⚠️ Gmail SMTP Rate Limits & Best Practices

- **Daily Limit**: standard Gmail accounts support up to 500 emails/day; Google Workspace accounts support up to 2,000 emails/day.
- **Batching**: The Express campaign handler processes subscriber batches sequentially with small delays between dispatches to prevent rate-limit throttling.
- **Error Recovery**: If an individual dispatch encounters an error, the error is recorded in `email_campaign_recipients.error_message`, and processing continues for the remaining recipients.
